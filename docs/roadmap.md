- 本地快速通道：严格整句匹配，支持中文数字和单位换算；docs 第 1–3 级例句全部命中；离线时识别不了就拒绝，不再按关键词猜。

### 2. voice-streaming（2026-11-12）

- 选型 spike：选定 OpenAI 实时转写 `gpt-4o-transcribe`，加简体中文 prompt，服务端 VAD 300 ms（`gpt-realtime-whisper` 的中文质量不够）。
- 边说边识别：分句一确定就路由，命中快速通道的立即执行；遇到第一个没命中的分句起，剩下的交给 LLM，并告诉 LLM 已执行的动作。
- LLM 改为每行输出一个动作（NDJSON），收到一行就执行一行。
- RobotAgent 改为执行队列，主循环不再等动作做完；"停"清空队列。
- 流式识别失败时回退到整句识别，只补上能确认的剩余动作。
- 合成语音回放 18 段：全部正确；松开到识别完成中位数 423 ms；多分句命令的第一个动作比说完提前约 2.8 秒。
- 开发中修复的问题：WebSocket 关闭要等约 2 秒、最后一个语段丢失的竞态、很短的话立刻松开时丢失、prompt 让"左夹子"被听成"把夹子"。

详见 `openspec/changes/voice-streaming/spike.md` 和 `measurements.md`。

### 4. voice-input-modes（2026-11-13，代码部分）

- 启动参数 `--input ptt|wake|cli`、`--pipeline stream|realtime`、`--hub sim|ble` 等，不用再改代码末尾；不合法的组合（如 `cli` + `realtime`、realtime 还没实现）提示原因后退出。VS Code 里有三个启动配置。
- 唤醒词改为**本地检测**：VAD 切句、按 2.5 秒切片，交给本地 faster-whisper tiny（CPU，约 300 ms/片段），只判断唤醒词和急停；**唤醒前不上传任何音频**。
- 选型时发现：按设计在 tiny 的提示词里写唤醒词，会把静音、噪声和普通聊天都"识别"成唤醒词。改为不用提示词，先做同音字归一（藍 / 欄 / 男 → 蓝）再模糊匹配：合成语音唤醒 5/5、聊天误唤醒 0/15。
- 所有云端音频调用都经过统一出口：未唤醒时拒绝上传，每次上传写一行审计日志（不含内容），默认 `logs/uploads.jsonl`。
- 唤醒后 20 秒连续对话：窗口内一开口就流式识别，停顿 0.7 秒（可配置）算说完；"结束对话"立即退出；可以一口气说"小蓝小蓝，前进30厘米"；没唤醒时喊"急停"也会停。
- 提示音改为后台播放，播放期间丢弃麦克风输入。
- 回放时发现并修复了一个**以前就有的问题**：音频很短时，云端识别会把提示词原样输出，里面的"停止"会触发误急停（按空格模式也会遇到）。
- 新工具 `python -m scripts.replay_wake`：用录音测试唤醒词模式。
- 顺手修复：simulate 模式的超时被缩得太小，有一个测试偶尔失败。

详见 `openspec/changes/voice-input-modes/measurements.md`。

### 5. voice-realtime-pipeline（2026-11-13，代码部分）

- `--pipeline realtime`：语音直接交给 OpenAI 实时模型（默认 `gpt-realtime-mini`，`--realtime-model` 可换），模型用函数调用给出动作；函数定义从技能自动生成，每个动作一个函数。
- 实测模型**每次回复只给一个函数调用**：每个调用到达就严格校验、入队，并回"已入队（这句话第 N 个动作）"，再请求下一个，直到模型不再调用工具。第一个动作入队时小车就开始动。
- 按空格：启动时建立会话，只在按住空格时上传；唤醒词：唤醒后才建立会话，窗口内音频连续上传、服务端判断句子边界，20 秒没人说话就关闭会话。
- 停止不依赖模型：转写中间文字或本地识别出停止词就立即急停、取消回复；两路先后报告同一个"停"时只发一次。
- 每句话独立：处理一句话之前删掉会话里之前几句话的上下文（保留时同一会话里第二次说"一共做四次"会少做一遍），也避免费用越积越多。
- 会话连不上或断开后重连失败：提示原因，自动切换到 stream 链路，正在说的那句改用整句识别。
- 新工具：`scripts.compare_pipelines`（两条链路对比）、`scripts.record_realtime_events`（录制接口事件做测试夹具）；`scripts.replay_wake --pipeline realtime`。
- 对比结论（合成语音）：简单命令 stream 更快（快速通道）；要交给 LLM 的句子 realtime 更快；realtime 直接"听"音频，个别句子不如专门的转写模型准。

详见 `openspec/changes/voice-realtime-pipeline/measurements.md`。

### 6. vision-field-model（2026-11-13，代码部分）

- 场地模型 `pc/field/data/wro_field.yaml`：WRO 练习场地（Starter 每年都用这块场地垫）的 A–D 区、起终点区、四个圆圈、命名位置点、黑线道路网、树和障碍杆的禁行区（默认关闭）、物体目录和默认目标。坐标从 `docs/WRO/WRO2022-ST-Aufgaben.pdf` 的总览照片矫正后测量，约 ±2 cm（摄像头到货后用参考图核对，任务 3.3）。
- 加载时校验：重复编号、引用不存在的位置点、超出场地、目标没有进入点、道路网不连通、接近方向不可行，都会指出具体错误并拒绝启动。替换了原来的 `pc/vision/map_config.yaml`（anchor 也在新文件里）。
- **物体可以随便摆**：布局是单独的文件（自带按 Starter 2022 任务书摆的 `starter2022`），模拟器还能生成随机布局。
- **摄像头感知（没有摄像头，用合成画面测试）**：新写了 `pc/vision`（旧的几个模块引用了不存在的模块，跑不起来，已删除）。
  - 摄像头采集：DirectShow、1080p、MJPG，尝试锁定对焦 / 曝光 / 白平衡，失败时警告。
  - 棋盘格内参标定工具（误差 > 1 像素不保存、分辨率不一致拒绝使用）。
  - 4 个场外 anchor 求相机位姿（缺哪个报哪个、不输出坐标），每 5 秒复查，三脚架被碰自动重算。
  - 小车定位：视线和 marker 高度平面求交，输出转弯中心、朝向、笼区中心；看不见时如实报告。
  - 俯视图、参考图、光照检查；差分检测物体（双阈值，同色物体在同色区域上也能检测）、按高度修正视差；开局按布局确定身份（匈牙利配对，报告缺少和多出），持续跟踪、被遮挡、被夹住跟着笼区。
  - 从参考图核对场地坐标（报告 > 2 cm 的偏差）；调试画面；`VisionSystem` 把这些串起来，直接接到导航层的接口。
  - 合成画面渲染器（场地垫、anchor、小车和车顶 marker、物体、棋盘格，含镜头畸变）：所有测试都用它。合成画面上定位误差约 0.1 cm、物体 ≤ 1 cm——只验证了几何，实际精度要实测。
  - anchor 的计划位置改到场地垫四角外面。
  - 详见 `openspec/changes/vision-field-model/measurements.md`；摄像头到货后的步骤见 README 第 15 节，实验 6-1–6-3。

### 7. navigation-grasp（2026-11-13，模拟器部分）

- 三个接口（小车位姿、物体检测、Hub）和真实系统的适配器；模拟器实现同样的接口，切换到实车只改配置。
- 运动学模拟器：误差和噪声可配置、随机种子、笼式夹爪（夹住随车走、压边被碰倒）、树和障碍杆会被碰倒、模拟时间（测试几秒跑完）；OpenCV 俯视图。
- 世界状态：物体六种状态（"已送达"部分接触也算）、夹爪状态只来自 Hub 回报、给 LLM 的结构化摘要。
- 道路网规划（禁行区、狭窄路口不拐弯、空旷处虚拟网格）；闭环 `go_to`：5% 误差下 150 次全部在 2 cm 以内；没有进展、看不见 marker 时暂停、超时、越界、随时停止。
- 笼式抓取和放下：预抓取点、引导点对准、分步接近、不在笼区内不放夹爪、验证和最多 3 次重试、一次只夹一个、区域里依次排开放下。
- 模拟整局（5% 误差）：Starter 2022 布局送达 88%，随机布局 70%，每局约 7 分钟（模拟时间）。**小车尺寸是估计值，结果对车宽很敏感**，实测后要重跑（`python -m scripts.sim_demo --stats 10`）。

详见 `openspec/changes/navigation-grasp/measurements.md`。

### 8. task-layer（2026-11-13，模拟器部分）

- 规则按 **2025 年**（用户确认）：`pc/task/data/missions.yaml` 的 `wro2025`——任务 1 三个小人送回同色区域（黄→A、绿→B、红→D），任务 2 蓝色大人→B，任务 3 包裹→D（原计划没写，暂按 2022），任务 4 服务机器人→同色圆圈，任务 5 停车。**还没有对照 2025 年任务书**；另有 `starter2022` 可切换。规则目标现在来自这个文件，不再取自场地模型。
- 演示布局 `wro2025_demo`：2022 的摆法里黄色、绿色小人开局就在自己的区域旁边（按 2025 规则已算送达），所以对调了这两个。
- 任务技能定义在 `skills/task.skill.md`（7 个：读取世界状态、move_object、go_to、pick、place、park、ask_user），物体和目标编号用枚举限定为场地模型里存在的；不影响原来的动作 registry。
- 任务代理（`pc/task/agent.py`）：LLM 工具调用循环，用户指定目标优先，有歧义先反问（30 秒没回答就取消），同一物体最多再试 1 次然后询问，30 次 / 5 分钟上限，喊"停"取消整个任务，每一步有进度（可选语音播报）。
- 语音交接 `run_task`：stream 链路是意图 LLM 输出的一行，realtime 链路是一个工具（录制了"完成任务二"的真实接口事件做夹具）；直接动作照旧走快速通道。反问时下一句话（语音或键盘）就是回答。
- 启动：`python -m pc.voice_to_robot --show-field`（默认 `--field sim`，任务在模拟场地里执行）；`python -m scripts.sim_task "完成任务1" --show`。
- 模拟器 + 真实 LLM（`gpt-5.5`，5% 误差）：完成任务1 9/9、服务机器人都送到圆圈 12/12、"把红色的送到D区" 3/3 先反问再送；每个物体约 1 次技能调用，规划延迟 2–3 s。

详见 `openspec/changes/task-layer/measurements.md`。
