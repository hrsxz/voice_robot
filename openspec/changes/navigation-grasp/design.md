# 设计：导航 + 抓取

## Context

- `vision-field-model` 提供：场地坐标系中的小车位姿（转弯中心、笼区中心、可见性）、物体检测和跟踪、场地模型（区域、圆圈、位置点、道路网、禁行区）。
- `hub-protocol-v2` 提供：动作开始和完成事件（ACK / DONE / STOPPED）、可打断的停止、夹爪角度回报。
- Hub 只支持离散动作：前进或后退 N 厘米、左转或右转 N 度、夹爪抬起或放下。
- 夹爪是笼式：放下后把车前一块区域圈住，物体可以在里面晃动。规则规定物体倒着、部分接触目标都算得分。
- 需求见 specs/，动机见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 用离散动作加视觉反馈，实现 2 厘米精度的闭环到达。
- 模拟器和实车共用同一套导航和抓取代码。

**Non-Goals:**
- 连续速度控制（`robot.drive`）和巡线辅助：以后可以作为提速或提高精度的手段。
- 动态障碍物检测：禁行区只用场地模型里固定的位置。

## Decisions

### D1 统一接口
定义三个接口：`PoseSource`（小车位姿）、`ObjectSource`（物体检测和跟踪）、`HubPort`（发送命令、等待事件）。真实实现分别包装 `vision-field-model` 和 `SpikeHub`，模拟器实现同样的三个接口；用一个配置项选择用哪套。

实现时补充：接口在 `pc/navigation/ports.py`。感知的适配器包装两个很小的约定：`localizer.latest()` 返回 found / x / y / heading / timestamp，`tracker.latest_objects()` 返回 id / x / y / visible / timestamp，都是场地坐标（厘米），由 `vision-field-model` 实现。`PoseSource` 还提供时钟：模拟器用模拟时间，所以"看不见 1 秒暂停、10 秒失败"这类逻辑在测试里不用真的等。

### D2 世界状态存储
一个对象汇总三方数据：感知更新位姿和物体，Hub 回报更新夹爪状态，抓取和放下更新"被夹住 / 已送达"。快照是不可变的数据类，并提供面向 LLM 的结构化摘要（名称、厘米坐标、状态）。"已送达"的判定：物体底面（按类型给出的圆半径）和目标的多边形或圆有交集。

### D3 路径规划
道路网的节点包括黑线交叉点、线端点、接近点和进入点，边沿着黑线，权重是长度，规模很小，用 Dijkstra 就够了。小车当前位置用一条不穿过禁行区的直线段连到最近的可达节点；最后一个节点再连到目标的接近点。

实现时补充（`pc/navigation/planner.py`，原因见 measurements.md）：
- 路线离障碍至少"车身半宽 + 2 cm"；走不通时再用 0.5 cm 试一次。已知的物体（不是这次要抓的）和树、障碍杆都算障碍。
- 离障碍或墙不够原地转向空间的节点（例如底部横线上 D 区方格旁边的路口）只能直行通过，不能在那里拐弯，也不能作为起点 / 终点的转向点。转向空间按夹爪状态算（抬起约 12.5 cm，放下约 23 cm）。所以按（节点，上一个节点）的状态做 Dijkstra。
- 离得很近（≤ 20 cm）的两个道路节点之间加直线捷径；场地中间没有黑线的地方加一个 15 cm 的虚拟网格（只放在空旷、能转向的地方，长度多算 20%，有黑线时仍然优先走黑线）。
- 起点 / 终点本身离某个障碍很近时（例如刚抓完物体），从那里出发的线段只要求不更靠近它。

### D4 闭环控制器
对每个路线点：
1. 计算朝向误差，超过 5° 就转向（`left` / `right` + 角度）。
2. 前进 min(剩余距离, 步长)：远处步长 30 cm，离目标 10 cm 以内时用 5 cm。
3. 等 Hub 回 DONE 之后再等 100 ms，取一帧新的位姿。
4. 误差进入容差就前往下一个路线点；每个路线点最多迭代 8 次。

越界检查放在每一步发出之前（按预测的终点加上车身半径和 5 cm 余量）。

实现时调整（`pc/navigation/controller.py`）：
- 越界余量改成规划时 0.5 cm、执行时 0.2 cm：2、3 号位的包裹离墙只有 5.5 cm，5 cm 余量会让它们永远够不着。车的外形随夹爪状态变化（抬起时夹爪竖着，不往前伸）。
- 每一步也检查会不会碰到障碍；原地转向会碰到墙或障碍时，广度优先搜索"转 15° / 直行 4 cm"的组合，挪到能转的地方（类似倒车入库）。
- 可以倒车：车尾对着目标后退（停进起终点区，或者转向会碰墙时）。
- 指定了最终朝向时，先到朝向线上的引导点（离目标 12 cm）对准方向，再直线开进去，到了目标就不用再原地转。
- 沿路线段走（纯追踪）：瞄准路线段上前方 30 cm 的一点，偏离路线后一步就回到线上。中间路线点的容差 2 cm；最后一个点内部按 1.5 cm 判断，给测量噪声留余量。
- 中间路线点离得很近、但贴着墙对不准时直接跳过。
- 备选：连续行驶加转向控制。否决：现有命令集是离散的；离散方式更好调试，也更容易向学生讲解。

### D5 抓取状态机
`前往预抓取点 → 对准物体 → 抬起夹爪 → 分步接近（每步 5 cm，同时修正左右偏差）→ 笼区判定 → 放下夹爪 → 验证 → 完成或重试`。
- 笼区几何（内宽、内深，相对笼区中心）和物体底面尺寸写在配置里。容差 =（笼区内宽 − 物体宽）/ 2 − 0.5 cm 余量。
- 最后几厘米物体常被车身挡住：用最后一次看到的相对位置加上已经发出的前进距离来推算，再靠验证步骤兜底。
- 验证：后退 3 cm，物体可见并且仍在笼区内 → 成功；物体留在原地 → 失败；看不见 → 再后退 5 cm 后重看，仍然看不见就算失败。

实现时补充（`pc/field/approach.py`、`pc/navigation/grasp.py`）：
- 接近时夹爪抬着，只有车身会碰到东西；只在抓取位姿检查夹爪放下后的完整外形。
- 预抓取点离抓取位姿默认 15 cm，地方不够时依次缩短到 12、10、8、5 cm（例如 2、3 号位和障碍杆之间）。
- 物体靠墙时让它靠近笼区前端（离转弯中心最多 cage_offset + 内深/2 − 半径 − 0.5），小车就能停得离墙远一点。
- 去预抓取点的路上，要抓的物体也算障碍（转弯时不能扫到它）；开始接近后才不算。
- 没有指定接近方向的位置（任意摆放），在 24 个方向里选离障碍最远的，正东南西北方向略优先。

### D6 放下
目标点取进入点到目标区域（或圆心）方向上，"笼区中心进入目标 3 cm 以上"的位置。到达后抬起夹爪，后退 10 cm，等物体重新可见，再按 D2 判定是否送达。

实现时补充：一个区域里要放好几个物体（4 个人都送到 B 区），所以沿区域从一端开始找空位（进入点左右平移，最多 ±21 cm），车（夹爪放下）离已经放好的物体至少 2 cm。圆圈只在 ±4.5 cm 内微调，尽量让笼区中心对准圆心。

停车：起终点区（约 26 cm 宽）比夹爪放下时的车短，所以停车 = 到进入点（车头朝东），再倒车到 park；规则只要求接触起终点区。

### D7 模拟器
二维运动学：小车是带朝向的刚体，物体是圆盘，笼区是车身坐标系里的矩形。噪声包括距离比例误差、每次转向的角度误差、位姿测量的高斯噪声，都可以配置，并且有随机种子。Hub 部分复用 `hub-protocol-v2` 的 simulate Hub 协议语义（动作时长、可打断）。俯视图用 OpenCV 画。

实现时补充（`pc/sim/`）：时间是模拟时间（按 motion_timing 的速度推进），`time_scale > 0` 时才真实等待，所以整局测试几秒就跑完，停止测试也能模拟"运动到一半被打断"。树和障碍杆是会被碰倒的物体，用来统计 WRO 的奖励分。物体可以按布局文件或随机布局摆放（布局见 vision-field-model 设计 D6 的调整）。`scripts/sim_demo.py` 跑一整局、实时显示或统计成功率。

### D8 失败处理
`go_to`、抓取、放下都返回结构化结果：`{status: ok | failed | stopped, reason, details}`，任务层根据原因决定重试还是询问用户。位姿不可见超过 1 秒就暂停（不发新动作），超过 10 秒就失败。

## Risks / Trade-offs

- [离散的走停太多，整体比较慢] → 调整步长；以后可以加连续控制。
- [动作结束后取到的是旧画面] → 等 DONE 之后再加 100 ms，并检查帧的时间戳。
- [转向打滑造成误差偏大] → 闭环会修正；可以按会话统计实际的转向比例，自动补偿。
- [大人和笼区之间余量小] → 最后阶段用更小的步长，也可能需要多一次重试。
- [抓取时把旁边的物体碰倒] → 世界状态会把它标为被移动，任务层重新规划；启用禁行区以后，接近路线会更保守。

## Migration Plan

- 新增模块，不影响语音链路。先在模拟器里完成开发和测试，摄像头到货后再接实车。
- 回滚：git revert。

## Open Questions

- 笼区的内宽、内深和各物体的底面尺寸：等实测，作为配置参数，不影响设计。现在的估计值见 `pc/config/robot_geometry.yaml` 和场地文件的物体目录；模拟结果对车宽很敏感（measurements.md），实测后要重跑统计。
- 各物体的具体接近方向：分析场地后写进场地模型数据（任务 3.1）。
