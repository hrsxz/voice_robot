# 设计：唤醒词 + 启动选择

## Context

- 现在的唤醒模式（`VoiceController.get_input_text` 的 `wake` 分支）：webrtcvad 录到句末（固定 67 帧，约 2 秒静音）→ 云端 STT（失败时用本地 Whisper）→ `ConversationGate.consume` 对文字开头做模糊匹配（rapidfuzz ≥ 75），然后进入 20 秒窗口。
- `whisper_stt.py` 已经有 faster-whisper 的封装，这台电脑没有 NVIDIA 显卡，只能用 CPU。
- `voice-streaming` 提供了流式识别客户端、执行队列和中间结果停止检测。
- 需求见 specs/，动机见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 唤醒前音频不出本机。
- 启动参数统一，四种组合（`ptt` / `wake` × `stream` / `realtime`）共用同一套命令处理和执行。

**Non-Goals:**
- realtime 链路本身（`voice-realtime-pipeline`）。
- 声纹识别或多人区分。

## Decisions

### D1 启动参数
`python pc/voice_to_robot.py --input ptt|wake|cli --pipeline stream|realtime --hub sim|ble`，同时保留 `VoiceController.run(...)` 的同名参数，方便在 IDE 里直接运行。启动时按组合表检查：`cli` + `realtime` 不合法；realtime 还没实现时一律提示不可用。

### D2 本地唤醒用 faster-whisper tiny
用 VAD 切出人声片段（不超过 2.5 秒），交给本地 faster-whisper `tiny`（CPU，int8），再对结果文字做模糊匹配。
- **不加 initial_prompt**（实现时修改，见 measurements.md）：加上唤醒词提示后，静音、噪声、只有尾音的短片段，甚至普通聊天（"到桌子上"）都被"识别"成"小蓝小蓝"，会大量误唤醒。
- 不加提示时 tiny 会把"小蓝"写成"小藍 / 小欄 / 小男"，"急停"写成"既停 / 鸡庭 / 集庭"。所以匹配前先做**同音字归一**（藍欄兰男… → 蓝，晓 → 小；既鸡集… → 急，庭亭… → 停），再用 rapidfuzz 在文字的任意位置找唤醒词（≥ 75 分）；匹配到的片段必须含"蓝"，否则"小明你好"也会有 75 分。
- 防止模型"脑补"：片段里人声少于 150 ms 不识别；去掉片段末尾的静音；`no_speech_prob` ≥ 0.6 的结果丢弃；`max_new_tokens` 限制为 24。
- 备选 Porcupine：需要注册账号、申请 AccessKey，中文自定义唤醒词还要单独生成模型，许可条款也要评估。暂不采用。
- 备选 openWakeWord：主要针对英文，中文唤醒词需要自己训练。暂不采用。
- tiny 模型复用现有依赖，唤醒前多 0.5–1 秒的延迟可以接受。识别率不够时再换 `base`，或者评估 Porcupine。

### D3 唤醒片段的命令部分交给云端识别
本地检测到唤醒词后，**这个片段本身**才上传云端做准确识别（本地 tiny 对数字的识别不够准），再从结果文字里去掉唤醒词，剩下的部分当作命令。窗口期内后面的话直接走 `voice-streaming` 的流式识别，用静音判断句末，而不是靠松开空格。

### D4 未唤醒时的急停
本地识别出的片段文字如果只有停止词（停止、急停、stop），就立即触发停止，不需要唤醒。这一步完全在本地，不上传。

### D5 连续对话窗口
保留 `ConversationGate` 的窗口逻辑（20 秒、每条命令续期、退出用语），但它判断唤醒的输入只来自本地识别的文字。云端只在窗口打开期间才会被调用，由 gate 的状态统一控制。

### D6 句末静音和提示音
- 句末静音时长改成参数（默认 700 ms），不再写死 67 帧。
- 提示音用后台任务播放，不等待；播放期间（约 250–300 ms，再加 100 ms 余量）把麦克风输入换成静音，避免提示音被 VAD 当成人声。
- 唤醒词后面紧接着还在说话时（一口气说命令），唤醒提示音推迟到这句话说完再响，不打断用户。

### D7 上传审计日志
每次向云端发送音频都在日志里记一行（时间、模式、窗口状态，不记录内容），用来验证"唤醒前不上传"。所有云端音频调用（整句识别、流式识别）都先经过 `UploadGuard.check()`：唤醒词模式下窗口没打开时直接拒绝（`UploadBlocked`），整句识别会回退到本地 Whisper。唤醒词模式默认写到 `logs/uploads.jsonl`。

### D8 云端识别的提示词回显（实现时新增）
回放测试中发现：音频很短或不清楚时，`gpt-4o-transcribe` 会把 STT 提示词原样输出（"向前走，往后退，……停止，……"），其中的"停止"被流式路由当成急停。这个问题在按空格模式也存在。处理：识别结果（整句和流式语段）和提示词高度相似时丢弃；流式识别的中间文字如果开头 9 个字以上和提示词一致，不交给急停检测。

### D9 唤醒片段的范围
唤醒词所在片段之前的片段（同一句话里的聊天）不上传；从唤醒词所在片段到这句话结束的音频才上传。说完唤醒词后本地识别还没出结果时用户就接着说命令，这句话在本地识别完成后补进对话窗口（音频已经缓存，不会丢）。

## Risks / Trade-offs

- [tiny 模型把"小蓝"听成"小兰""晓岚""小男"] → 同音字归一加模糊匹配（D2）；识别率不够时换 `base`。
- [本地 tiny 偶尔很慢（很短的"嗯"用了 1.2–1.6 秒）] → 只影响唤醒的反应时间；`max_new_tokens` 限制最坏情况。
- [句末静音 0.7 秒会把"前进50厘米（停顿）然后右转"切成两句] → 两句按顺序执行，结果一样；但第二句交给 LLM 时不知道第一句（不像按空格模式整句都在一个会话里）。需要时调大 `--end-silence-ms`。
- [误唤醒] → 只是打开了对话窗口，没有命令就不会动；把误唤醒次数记录下来，用于调整阈值。
- [漏唤醒] → 用户再说一遍就行；记录漏唤醒的情况。
- [本地识别占用 CPU] → 只在检测到人声时才运行。
- [丢弃提示音期间的输入，可能吞掉用户刚开口的一点声音] → 丢弃时间很短，而且 VAD 有预录缓冲（pre-roll）。

## Migration Plan

- 默认启动参数保持现在的行为（按空格模式），`wake` 需要显式选择。
- 回滚：git revert；旧的云端唤醒逻辑不再保留。

## Open Questions

- 唤醒词最终用哪几个（现在是"你好小蓝 / 小蓝小蓝"）：可以随时在配置里改，不影响设计。
