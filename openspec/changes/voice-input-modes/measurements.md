# 测量记录：voice-input-modes

## 1. 本地唤醒模型选型（任务 2.1，2026-11-13）

**环境**：开发笔记本，CPU（没有 NVIDIA 显卡），faster-whisper 1.2.1，模型 `tiny`（多语言版），int8，线程数 = CPU 核数 − 1。

**音频**：OpenAI TTS 合成的语音（`python -m scripts.make_test_audio`，`tests/fixtures/audio/wake/`），没有用真人录音：5 段唤醒（小蓝小蓝 / 你好小蓝 / 唤醒词后接命令 / 唤醒词在一句话中间 / 一口气说完），1 段急停，4 段聊天（其中一段含"蓝色"，一段含"小明你好"）。

### 1.1 initial_prompt 的影响

同样的片段分别加和不加 `initial_prompt="小蓝小蓝，你好小蓝，急停，停止。"`：

| 输入 | 加 prompt | 不加 prompt |
|---|---|---|
| 纯静音 2 秒 | 小蓝小蓝 | （空） |
| 白噪声 2 秒 | 小蓝小蓝小蓝小蓝小蓝小蓝 | （空） |
| 句末只有尾音的短片段（0.1–1.1 秒，共 8 个） | 全部输出"小蓝小蓝…" | 全部为空 |
| 聊天"……放到桌子上"的第 2 段 | **小蓝小蓝**（no_speech_prob = 0.00） | 到脱子上 |
| 聊天"小明你好" | 小蓝你好 | 小明你好 |
| "小蓝小蓝" | 小蓝小蓝 | 小男 小男 |
| "你好小蓝" | 你好小蓝 | 你好小男 |
| "急停" | 既停 | 鸡庭 |

**结论**：加 prompt 会大量误唤醒（连普通聊天都会），不能用。改为不加 prompt，用同音字归一 + 模糊匹配（design.md D2）。

### 1.2 不加 prompt 的识别结果（经过完整的唤醒主循环：真实 VAD + 切片 + tiny）

| 录音 | 本地识别 | 判断 |
|---|---|---|
| wake_only（小蓝小蓝） | 小男 小男 | 唤醒 ✓ |
| wake_hello（你好小蓝） | 你好小男 | 唤醒 ✓ |
| wake_forward_30（小蓝小蓝，前进三十厘米） | 小欄 小欄 | 唤醒 ✓ |
| wake_forward_30_fast（一口气说完） | 小欄小欄 前进生 | 唤醒 ✓ |
| wake_in_middle（嗯那个，我想想，小蓝小蓝，向左转九十度） | 恩 / 我想想 / 小男小男（另一次运行：等 那個 / 我想想 / 小蓝小蓝） | 第 3 段唤醒 ✓ |
| wake_stop（急停） | 集庭 | 急停 ✓ |
| 4 段聊天，共 15 个片段 | 把藍色的機幕放到 / 小明你好 / 今天天起真不错 / …… | 全部忽略 ✓ |

唤醒 5/5，急停 1/1，聊天误唤醒 0/15（合成语音，样本很少；真人和背景聊天的误唤醒率见实验 4.2）。

### 1.3 耗时

单个片段（≤ 2.5 秒）的本地识别耗时，3 次回放共约 30 个片段：

- 中位数 **约 300 ms**（249–462 ms）
- 偶尔很慢：很短的"嗯那个"分别用了 1216 ms 和 1601 ms（模型反复输出，已用 `max_new_tokens=24` 限制）
- 模型加载约 9 秒（第一次运行时下载约 75 MB）；启动时加载，不影响第一次唤醒

## 2. 唤醒前不上传（任务 2.3）

- 单元测试：mock 云端客户端，回放 4 句聊天（含 4 秒长句），整句识别调用 0 次、流式识别连接 0 次、审计日志文件不存在。
- 真实模型回放：4 段聊天录音（共 41 秒），上传 **0 次**；之后的唤醒录音，每次上传时窗口都已打开。

## 3. 唤醒词后接命令（任务 2.4）

| 录音 | 结果 |
|---|---|
| wake_forward_30_fast（"小蓝小蓝前进三十厘米"，不停顿） | 唤醒片段上传 → 云端"小兰小兰，前进三十厘米。" → 去掉唤醒词 → `forward 30` ✓（唤醒片段整句识别耗时 1.3 秒） |
| wake_forward_30（"小蓝小蓝，前进三十厘米"，中间停顿 0.6 秒 + TTS 尾音） | 被切成两句：唤醒 → 第二句走流式识别 → `forward 30` ✓ |

## 4. 对话窗口（任务 3.1）

`python -m scripts.replay_wake --keep-window --gap 3 wake_only l1_left_90 l1_forward_30 l2_forward_right`：唤醒一次后连续 4 条命令（`left 90`、`forward 30`、`forward 50`、`right 90`）都执行，不用再唤醒；窗口内的话不经过本地识别。

`--gap 22 wake_only l1_left_90`：唤醒后 22 秒没说话 → "连续对话已超时"；之后的"向左转90度"只在本地识别，没有上传、没有执行 ✓。

## 5. 句末静音（任务 3.2）

合成语音 `l1_forward_30.wav` + 真实 webrtcvad：最后一个人声帧之后，静音达到设定时长（700 ms → 24 帧 = 720 ms；400 ms → 14 帧 = 420 ms）时这句话结束（`tests/test_wake_mode.py::SegmenterRealAudioTest`）。

## 6. 回放中发现的问题：云端识别的提示词回显

`wake_in_middle` 回放时，`gpt-4o-transcribe` 两次把 STT 提示词原样输出：

```
向前走，往后退，向左转，向右转，停止，左夹子抬起来，左夹子放下来，右夹子抬起来，右夹子放下来，……，一共做四次。
```

第二次出现在流式识别中，里面的"停止"触发了急停，导致后面的"向左转九十度"没有执行。按空格模式也可能遇到（例如按下空格但几乎没说话）。修复后（design.md D8）同一段录音：回显语段被丢弃，`left 90` 正常执行。
