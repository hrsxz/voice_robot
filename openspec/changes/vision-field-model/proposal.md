# 提案：感知 + 场地模型（vision-field-model）

## Why

要让小车自主完成"把物体送到区域"这类任务，系统首先得知道小车和物体在场地上的位置（厘米）。现在的视觉代码有几个问题：导入路径错误，根本跑不起来；只输出像素坐标；红色检测器会把整个红色 D 区当成物体；也没有处理三脚架斜拍造成的视差（远角偏差可达十几厘米）。场地是 WRO Starter 2025 的标准场地，物体的起始布局由规则定死，可以充分利用这一点。

## What Changes

- 修复 `pc/vision` 的导入错误，让视觉系统能运行。
- 摄像头使用 1080p，在支持的情况下锁定自动对焦、自动曝光、自动白平衡。
- 新增镜头内参标定工具（棋盘格），结果保存后重复使用。
- 启动时用放在场地垫外的 4 个 ArUco anchor 计算相机位姿，运行中检测三脚架是否被碰歪。
- 小车定位：车顶一个 marker，用视线和"marker 高度平面"求交点，得到场地坐标和朝向（已修正视差），并换算出转弯中心和笼区中心。
- **BREAKING**：新的场地模型 YAML 替代 `pc/vision/map_config.yaml`，描述区域、起终点区、圆圈、位置点、任务物体（类型、颜色、高度、起点、目标）、道路网（黑线）和禁行区（树、障碍杆，默认关闭）。
- 物体检测：在矫正成俯视图的画面上和空场地参考图做差分，排除小车所在区域，再判断颜色，并按物体高度修正视差。
- 物体跟踪：开局按已知起始布局确定每个物体的身份，之后持续更新位置；被夹住的物体跟着小车走。
- 新增调试窗口，以及从参考图自动提取区域边界的辅助工具。

## Capabilities

### New Capabilities

- `camera-calibration`：镜头内参标定、相机相对场地的位姿、位姿漂移检测和相机参数锁定。
- `robot-localization`：根据车顶 marker 计算小车在场地上的位置和朝向，包括视差修正和关键点偏移。
- `field-model`：描述场地固定元素、任务物体初始布局、道路网和禁行区的配置及其校验。
- `object-tracking`：任务物体的检测、身份确定和持续跟踪。

### Modified Capabilities

- 无

## Impact

- **代码**：`pc/vision/*` 基本重写，新增标定工具、场地模型加载器和场地数据文件；删除 `map_config.yaml`。
- **硬件**：需要支持 1080p 的外接摄像头和三脚架；打印棋盘格、4 个 anchor（8 cm）和 1 个车顶 marker（8–10 cm）。
- **依赖**：沿用 OpenCV（含 aruco 模块）、numpy、PyYAML，不新增依赖。
- **待提供的资料**：摄像头型号和参数、小车照片和尺寸（marker 高度、偏移量）、三脚架位置的实拍画面。它们都作为配置参数，不影响方案本身。
- **数据保护**：摄像头只拍场地；调试截图里如果拍到人，不应该长期保存。
