# 设计：感知 + 场地模型

## Context

- 现有的 `pc/vision`：`MapCalibrator` 用 4 个 anchor 计算单应矩阵（像素 → 厘米），逻辑本身可用；`ArucoPoseTracker` 只输出像素坐标，朝向也是在像素空间里算的；`RedBlockDetector` 找画面里最大的一片红色；`vision_system.py` 和 `robot_pose_tracker.py` 引用了不存在的模块，现在跑不起来。
- 场地是 WRO 标准场地垫（2362 × 1143 mm）。三脚架架高斜拍，地图会铺满约 70° 的视场，所以四角落在畸变最大的画面边缘。
- 小车顶部离地约 10 cm（不超过 25 cm），用一个 8–10 cm 的 marker；夹爪是笼式。
- 需求见 specs/，动机见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 位置精度不超过 2 cm，朝向精度不超过 3°，在场地任何位置都满足。
- 对摄像头型号、三脚架位置、小车尺寸这些参数可以通过配置适配，换了摄像头或小车不用改代码。

**Non-Goals:**
- 训练物体识别模型。
- 场地垫以外的一般场景。
- 多台摄像头。

## Decisions

### D1 场地坐标系
原点在场地垫左上角（A 区所在的角，和规则示意图的方向一致），x 向右（0–236.2 cm），y 向下（0–114.3 cm），z 向上，单位厘米。朝向 0° 指向 +x，顺时针为正（因为 y 向下）。所有模块统一使用这个坐标系。

### D2 摄像头采集
Windows 下用 OpenCV 的 DirectShow 后端：设置 1920×1080 和 MJPG（保证帧率），尝试关闭自动对焦、自动曝光、自动白平衡，然后读回属性确认。设置不成功时按 spec 发出警告。

### D3 内参标定用棋盘格
采集 15–20 张棋盘格照片（例如 9×6 个内角点，格子 25 mm），计算内参和畸变系数，连同分辨率一起保存为 YAML。
- 备选 ChArUco：对部分遮挡更鲁棒，但打印和讲解都更复杂。棋盘格对课堂演示更直观。

### D4 外参：4 个场外 anchor + solvePnP
4 个 anchor（ID 10–13，8 cm）贴在场地垫外的桌面上，与场地边对齐摆放，它们在场地坐标系中的中心位置和朝向写进场地模型。用全部 16 个角点做 solvePnP 求相机位姿（场地垫厚度忽略不计）。之后每 5 秒复查一次，偏差超过 1 cm 就重新计算并发出警告。

### D5 小车位姿：视线与 marker 高度平面求交
marker 的 4 个角点像素 → 去畸变 → 从相机中心出发的视线 → 与平面 z = h（marker 离地高度）求交 → 得到 4 个角点的场地坐标 → 中心和朝向（由角点顺序决定）。再在车身坐标系里加上偏移：marker 中心 → 转弯中心 → 笼区中心。marker ID（默认 20）、边长、高度和偏移量都写在配置里。
- 备选 A：单应矩阵 + 以相机正下方为中心的缩放修正（不需要内参）。否决：画面边缘的镜头畸变本来就要求做内参标定。
- 备选 B：OpenCV 的单 marker 6 自由度位姿估计。否决：单目深度方向噪声大；已知高度的视线求交更准。

### D6 场地模型 YAML
一份文件包含：`field`（尺寸）、`anchors`、`zones`、`start_area`、`circles`、`positions`、`objects`（物体目录：类型、颜色、高度、底面半径、默认目标）、`roads`（`nodes` 和 `edges`）、`keepouts`。再用区域自动提取工具在真实参考图上交叉核对，偏差超过 2 cm 的地方会被报告出来。

实现时调整（2026-11-13）：
- 物体可以随意摆放，所以起始位置不写在场地文件里，而是单独的布局文件（`layouts/*.yaml`，每个物体引用一个命名位置点或直接给坐标）。自带 `starter2022` 布局，按 `docs/WRO/WRO2022-ST-Aufgaben.pdf` 摆放；以后有了别的年份的任务书，再加一份布局即可。摄像头到位后，起点直接来自开局检测；模拟器可以随机生成合法布局。
- 没有矢量的场地垫文件：坐标从任务书里的总览照片测量（四角做透视矫正，四个圆的半径在 x、y 方向都量出 5.0 cm，说明矫正可信），精度约 ±2 cm，由任务 3.3 的参考图核对兜底。

### D7 矫正俯视图
去畸变后的画面按相机位姿投影到 z = 0 平面，生成 4 px/cm 的俯视图（约 945 × 457 像素），用于参考图、差分和区域提取。地面上的东西在俯视图里是准确的；有高度的物体会朝远离相机的方向"拉长"，这一点在 D8 里处理。

### D8 物体检测
当前俯视图和参考图在 Lab 色彩空间里做差分 → 阈值 → 形态学处理 → 连通区域 → 去掉小车的车身区域（由位姿和车身轮廓算出）→ 按区域内像素的色相判断颜色。位置的计算：取区域的质心，再按物体高度的一半，朝相机正下方的点做缩放修正。物体高度在场地模型中按类型给出。

### D9 身份确定和跟踪
- 开局：按颜色约束，用匈牙利算法把检测结果和起始位置一一配对，配不上的分别报告为"缺少"或"多出"。
- 运行中：每个已知物体在一定范围内寻找最近的同色检测结果；找不到就保留原位置并标为"被遮挡"。被标为"被夹住"的物体，位置直接取笼区中心（这个标记由 `navigation-grasp` 设置）。

### D10 光照检查
比较参考图和当前画面里静态区域（不在物体或小车附近的地方）的平均亮度，偏差超过阈值就警告。

### D11 修复和整理现有代码
统一模块名（`data_types`、`target_detector`、`robot_pose_tracker` 等），修复导入错误；`RedBlockDetector` 被差分检测取代，`MapCalibrator` 的单应矩阵逻辑并入 D7 的矫正俯视图。

实现时的调整（2026-11-13）：
- 旧模块（`calibration.py` 的 `MapCalibrator`、`robot_pose_tracker.py`、`target_detector.py`、`data_types.py`）直接删除，由新模块取代：`camera_model`、`extrinsics`、`localizer`、`topview`、`objects`、`tracker`、`field_check`、`debug_view`、`vision_system`。参数集中在 `pc/config/vision.yaml`，本机的标定结果和参考图放在 `pc/config/local/`（不提交）。
- anchor 的计划位置改到场地垫四角外面（各向外 7 cm），符合 D4"贴在场地垫外的桌面上"；贴好后按实测改。
- 物体检测加了双阈值：和强差异区域相连的弱差异像素也算。没有它时，蓝色大人站在蓝色 C 区里只检测出一部分，位置偏 2.7 cm；加了以后 0.35 cm。
- 光照检查排除的是小车和已检测物体附近的区域（不是全部差分像素：光照变化很大时几乎所有像素都"不同"，会把比较区域排除光）。
- 为了在没有摄像头时测试，新增合成画面渲染（`synthetic.py`）：按已知的内参（含畸变）和相机位姿渲染场地垫、anchor、小车（车身 + 车顶 marker）、物体（圆柱）和棋盘格。

## Risks / Trade-offs

- [摄像头不能关闭自动对焦，内参会漂移] → 启动时警告；采购时选择能手动对焦的摄像头。
- [小车和物体的影子造成差分误检] → 设置面积和颜色饱和度门槛；灯光尽量固定、从上方照射。
- [物体靠得很近时，差分区域粘在一起] → 结合已知的物体数量和颜色拆分；规则里的起始间距足够大。
- [远角分辨率不够，marker 识别不稳定] → 1080p 加 8–10 cm 的 marker；必要时再加第二个 marker。
- [官方场地文件和实际印刷有偏差] → 用区域自动提取工具交叉核对。
- [BREAKING：map_config.yaml 被替换] → 目前没有其他模块依赖它。

## Open Questions

- 摄像头型号和视场角：标定时会测出来，不影响方案。
- marker 离地高度，以及 marker → 转弯中心 → 笼区中心的偏移：等小车照片和实测数据，作为配置参数。
- 三脚架摆放位置：按 D4 的流程，放在哪里都能自动算出位姿；具体位置以拍出来的实际画面为准。
