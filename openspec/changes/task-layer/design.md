# 设计：任务层

## Context

- `navigation-grasp` 提供：世界状态快照和面向 LLM 的摘要；`go_to` / 抓取 / 放下技能，返回 `{status, reason, details}`；模拟器。
- 语音链路：stream 链路里，快速通道没命中就交给意图 LLM（每行一个底层动作）；realtime 链路里，模型调用动作工具。两者都进入同一个执行队列。
- 场地模型里有每个物体的规则目标、接近方向和进入点。
- 需求见 specs/，动机见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 语音层只判断"直接动作还是目标"；规划和执行反馈的循环全部在任务代理里完成。
- 在模拟器里能完整跑通任务，并能自动化测试。

**Non-Goals:**
- 同时执行多个任务。
- 赛场计时和计分逻辑（这是教学演示，不是比赛）。

## Decisions

### D1 两层结构，用 `run_task(goal)` 交接
意图层（快速通道 / 意图 LLM / realtime 模型）只多一个工具或动作 `run_task(goal: str)`：遇到目标级请求就把原话交给任务代理。任务代理是一个独立的文本 LLM 工具调用循环。
- 备选：让意图 LLM 直接输出 `move_object` 这类行。否决：一次性输出无法根据执行结果调整，处理不了失败和歧义。

### D2 技能粒度
`move_object` 是组合技能（前往预抓取点 → 抓取 → 前往目标进入点 → 放下），由 `navigation-grasp` 确定性地实现。任务代理优先使用它；`go_to`、`pick`、`place` 用于失败恢复，或者用户提出的特殊要求（比如"把黄色小人带到 B 区附近先别放下"）。`park` = 前往起终点区。

### D3 技能定义来源
新建 `skills/task.skill.md`，路由为 `task`，沿用 frontmatter + `input_schema` 的写法。工具定义的生成器和 `voice-realtime-pipeline` 共用：哪个改动先实现，就把生成器放进共享模块。

### D4 世界信息怎样给 LLM
系统提示里包括：机器人能力说明、规则（D6、D7）、任务组列表，以及开局时的世界摘要。每个技能的返回结果里附带"状态有变化的物体"，代理也可以随时调用 `get_world_state` 获取完整快照。

### D5 任务组配置
`missions.yaml`：编号（1–5）、中文和德文别名、包含的物体和各自的规则目标，任务 5 是停车。放进系统提示，让代理能理解"任务 1""送小人回家"这样的说法。

实现时的调整（2026-11-13）：规则目标**写在 `missions.yaml` 里**，不再取自场地模型——场地模型物体目录里的目标是按 2022 年任务书写的（所有人都送到 B 区），而这里按 2025 年的说法（小人送回同色区域）。文件里可以有多份规则（`wro2025` 默认、`starter2022`），启动时选择；没有出现在任何任务里的物体才用场地模型的目标。`wro2025` 按原计划整理、还没有对照任务书，任务 3 原计划没写，暂按 2022 年（包裹→D 区）。

配套的演示布局 `wro2025_demo`：Starter 2022 的摆法里黄色、绿色小人开局就在 A、B 区旁边，按 2025 规则已经算"送达"，所以对调这两个小人。

### D6 目标优先级
系统提示和代码校验共同保证：用户话里明确给出了目标，就用这个目标（只要它是有效的区域或圆圈）；只说任务编号或者"送回家"之类的说法时，才用规则目标。`move_object` 会校验目标编号必须在场地模型中存在。

### D7 反问
提供 `ask_user(question, options)` 工具：在终端显示（启用语音播报时同时播报）问题和选项，等待下一句语音或键盘输入（30 秒超时），把回答文字作为工具结果返回。等待期间小车不动。系统提示规定：引用对应多个物体或目标时必须先问。

### D8 失败策略和上限
- 技能内部已经包含重试（例如抓取最多 3 次）。代理层面，同一个物体的 `move_object` 最多再试 1 次，之后就向用户报告并询问是否继续。
- 硬上限：每个任务最多 30 次技能调用，最长 5 分钟；达到上限就停止，并汇总已完成和未完成的部分。

### D9 停止
停止事件会取消代理的异步任务，并中止正在执行的技能（导航层的中止）；对话以"已停止"结束，不再调用 LLM。

### D10 模型选择
任务代理使用能力更强的模型（可配置），和意图层的快速小模型分开。规划延迟只出现在任务开始和失败之后，相对于小车的行驶时间可以接受。

### D11 测试
单元测试用 mock 的 LLM 按脚本给出工具调用，覆盖歧义、失败、上限、停止等路径；集成测试在模拟器里接真实 LLM 运行（结果不完全确定，手动运行并记录）。

## Risks / Trade-offs

- [LLM 规划出不合理的调用，比如没夹着东西就调用放下] → 技能会检查前置条件并返回错误，代理根据错误调整。
- [LLM 编造不存在的物体编号] → 工具参数用枚举限定为世界状态里的编号，再加上代码校验。
- [多轮调用的费用和延迟] → 步数上限；优先使用 `move_object` 组合技能，减少轮数。
- [反问等待时用户走开了] → 30 秒超时后取消任务，并提示。

## Migration Plan

- 新增模块和一个交接工具，对直接动作没有影响。先在模拟器里验证，再接实车。
- 回滚：从意图提示词中去掉 `run_task`，或者 git revert。

## Open Questions

- 任务代理用哪个模型：可配置，实测后再选，不影响设计。
