# Spec Delta

## Purpose

测量并输出每条语音命令在各处理环节的耗时，为延迟优化和不同语音链路的对比提供数据依据，同时不记录音频等多余的个人数据。

## ADDED Requirements

### Requirement: 每条命令输出耗时汇总
系统 SHALL 为每条语音命令输出一行耗时汇总，起点是录音结束，内容包括 STT、路由（快速通道或 LLM）、BLE 发出、Hub 确认各段的耗时和总耗时，并标明这条命令走的是哪种路由。

#### Scenario: 快速通道命令
- **WHEN** 一条命令走本地快速通道执行
- **THEN** 汇总行包含 STT、路由、BLE 发出、Hub 确认各段耗时，路由标记为"快速通道"，并且没有 LLM 耗时

#### Scenario: LLM 命令
- **WHEN** 一条命令交给 LLM 处理后执行
- **THEN** 汇总行包含 LLM 耗时，路由标记为"LLM"

#### Scenario: 某一环节失败
- **WHEN** STT、LLM 或 Hub 通信中的某一环节失败
- **THEN** 汇总行仍然输出已完成环节的耗时，并标明失败的环节

### Requirement: 耗时记录可写入本地文件
系统 SHALL 支持把每条命令的耗时记录以每行一条结构化记录（JSON 行）的形式追加写入本地日志文件，用于之后统计中位数和对比不同配置。

#### Scenario: 启用日志文件
- **WHEN** 启用了耗时日志文件并执行了 3 条命令
- **THEN** 日志文件里追加了 3 条记录，每条都包含时间戳、各段耗时、路由类型和最终命令

### Requirement: 耗时记录不包含音频
耗时记录 MUST NOT 包含音频数据或音频文件路径，只能包含时间戳、耗时、路由类型、识别出的文字和最终命令。

#### Scenario: 检查日志内容
- **WHEN** 查看任意一条耗时记录
- **THEN** 记录里没有音频内容，也没有录音文件的路径
